# Fine-tune dataset — pharmacy tool-use (T-D3)

**Status: MACHINE-DRAFTED, NOT native-reviewed. Training deferred to the GPU box (T-D4).**

## What this is
A supervised fine-tuning (SFT) dataset that teaches **tool-calling** for the pharmacy agent on
`Qwen3-4B-Instruct-2507`. Every example maps a customer message (Arabic dialects / English, with
Najdi texture) to the **correct tool call(s)** from the 8-action contract — never a chat reply.

- `data/sft_train.jsonl` (334) / `data/sft_test.jsonl` (56) — held-out test, never to be trained on.
- Format per line: `{"messages": [...], "tools": [...]}` in OpenAI/Qwen tool-call format
  (assistant turns carry `tool_calls`; prior `tool` results included for multi-turn examples).
- Grounded in the live Odoo catalogue: real product variant ids, branch ids, and
  scheduled/restricted flags, so tool-call arguments are valid.
- `customer_id` is deliberately **omitted** from create_order/hold_item/track_order targets —
  the agent injects it at runtime; the model must not invent it.

## Composition (balanced)
search 180 · check_stock(mt) 30 · create_order(mt) 30 · hold_item(mt) 30 · track 16 ·
list_branches 12 · escalate_medical 36 · escalate_scheduled 24 · escalate_restricted 16 ·
unclear 8 (one clarifying question — clarify-once) · abusive 8. (~390 total.)

Behaviours taught: product mention→search_product first; branch name→list_branches; status→
track_order; medical/dosage→escalate(medical_advice); scheduled/prescription→escalate
(restricted_item); abusive→escalate(abusive); vague→one clarifying question; multi-turn
check_stock/create_order/hold_item with resolved ids; confirm before create_order.

## Provenance / licensing
- Dialect texture (greetings, request verbs أبي/ابغى/ودي, question words وش/كم/وين) was mined
  from **HeshamHaroon/saudi-dialect-conversations** (Najdi, **Apache-2.0**, synthetic/GPT-4o) via
  `mine_phrases.py`. That dataset's *content* is NOT used (it's general-life chat); only its
  dialect phrasing informs the templates in `build_sft.py`. See docs/sources.md.
- All examples are generated by `build_sft.py` (templates × Odoo data × dialect frames).

## Caveats (must address before trusting)
- **Native-speaker review required** on the Arabic before any trained model is treated as
  accuracy evidence (plan rule 3). Templated Arabic can be stilted.
- Synthetic, template-based → limited phrasing diversity; expand templates / add real WhatsApp
  logs (when available) before scaling up.
- Rebuild any time: `python finetune/mine_phrases.py && python finetune/build_sft.py`
  (needs Odoo up; the raw parquet is gitignored and re-downloaded by mine step's source URL).

## Training (on the GPU box — T-D4, not run here)
`finetune/train_qlora.py` is a ready QLoRA script (unsloth + trl). Run it on the L40S:
it loads the base, trains the adapter on sft_train.jsonl, evals on sft_test.jsonl, saves the
adapter + a merged model, and notes GGUF export for Ollama. Keep the fine-tune only if it beats
the baseline AND adds no new wrong-action cases (plan T-D5).
